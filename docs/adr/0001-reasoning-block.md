# ADR 0001: 将模型思考作为会话时间线中的独立区块

- 状态：已接受
- 日期：2026-09-18

## 背景

当前 OpenAI 兼容流式响应可以收到 `reasoning` 或 `reasoning_content`，但应用只用它切换到 `Thinking...` 状态，不保存 reasoning 原文。会话消息当前主要承载用户消息、assistant 消息、工具消息和事件消息。

产品需要让用户查看模型返回的完整思考内容：思考过程中可查看实时内容，思考结束后默认只显示 `Thinking` 栏，点击后展开完整原文。

## 决策

### 领域对象

将 `ReasoningBlock` 作为 `Session` 时间线中的独立项。它不是 assistant 正文的附属展示文本，也不是工具调用的属性。

每次成功的模型请求最多产生一个 `ReasoningBlock`：

- 收到首个 reasoning 内容后才创建；没有 reasoning 内容时不创建空块。
- 即使该请求只返回 reasoning 和 tool call、没有可见 assistant 正文，也保留该块。
- 块位于对应模型结果之前，并按会话时间线顺序显示。

### 持久化与失败语义

- 原文完整持久化，保留 provider 返回的文本和换行，不做摘要或字符截断。
- reasoning 只在对应模型请求成功后落库。
- 失败、取消或进程中断的请求，即使已经收到部分 reasoning，也丢弃该部分内容。
- LLM 重试只保留最终成功请求的 reasoning；失败尝试不单独形成历史块。
- 展开/收起状态属于 UI 会话状态，不改变领域数据，也不要求写入数据库。

### 上下文边界

Reasoning 原文只用于展示和审计：

- 不作为后续 provider 请求的对话消息。
- 不进入 compact 摘要。
- 不改变模型实际看到的 user、assistant 和 tool 上下文。

### 展示状态

- 生命周期为 `Absent -> Streaming -> Completed`；失败或取消时从 `Streaming -> Discarded`，`Collapsed/Expanded` 只属于 `Completed` 的 UI 展示状态。
- 新建块默认收起。
- 生成中且收起时显示最新四行内容；展开时显示当前已收到的全部内容。
- 生成结束且收起时不显示正文，只显示 `Thinking` 栏。
- 生成中标题为 `Thinking...`，生成结束标题为 `Thinking`。
- 每个块独立维护展开状态；用户在生成中展开后，生成结束仍保持展开。
- 离开并重新进入会话时，所有历史块重新默认收起。
- 收到首段 reasoning 前沿用现有运行中的 `Thinking...` 占位；模型不返回 reasoning 时不留下空块。
- 流式内容更新时仅在列表已经位于底部的情况下自动跟随；用户向上查看历史后暂停自动滚动，回到底部后恢复跟随。
- 收起态预览按原文换行取最后四行，并限制为约四个视觉行高；长行超出容器时裁切，展开后显示完整内容。

## 结果

实现需要把流式 reasoning 从“仅有通知”升级为“带文本的增量事件”，并在成功响应完成时将该文本作为独立时间线项保存。UI 需要同时处理进行中的内存块和已经持久化的历史块。

数据库中的 reasoning 记录必须继续被 API 消息组装逻辑排除，避免展示数据污染模型上下文或增加 token 消耗。

本决策没有规定具体的 Room 存储形态；实现可以复用现有消息时间线，只要保留上述领域语义、顺序和生命周期。
